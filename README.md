# repo2draw

English | [中文](README.zh.md)

**Zero-AI architecture diagram, auto-synced into your README.**
It statically analyzes your repository, renders the module graph as an
`x-cmd draw` chart URL, and keeps it updated between markers in your
`README.md` — no LLM calls, no PNG/SVG files. The diagram *is* a URL.

## What it does

- **Watches your repo and keeps the README diagram fresh** — runs on pushes to your default branch (source paths only) or on demand; commits the updated README back as `github-actions[bot]`.
- **Understands 9 languages** (Python, Node.js, Go, Rust, Java/Kotlin, C#, PHP, Ruby, Swift, C/C++) and falls back to a directory-tree diagram for anything else — every repo gets a picture.
- **Zero AI, zero dependencies** — pure regex/static analysis with the Python 3 standard library; a run takes ~10s. No SDKs, no API keys.
- **One line to adopt** — `- uses: qiakai/repo2draw@main` in a workflow; nothing to vendor.
- **Honest, readable charts** — nodes typed by module name (Database / Frontend / Backend / Message bus / …), cycle-safe layered layout, top-level directory boundary boxes, ≤15 nodes so it never becomes a spider web.
- **No binary assets** — the chart is a URL rendered by [x-cmd draw](https://x-cmd.com/draw); your git history stays text-only.

## Supported project languages

| Language | Detected by | Extracts dependencies from |
| --- | --- | --- |
| Python | `pyproject.toml` / `requirements.txt` / `setup.py` | `import`, `from X import Y` (incl. relative) |
| Node.js | `package.json` | `require`, `import … from` (incl. `@/` aliases) |
| Go | `go.mod` | `import` blocks + module path |
| Rust | `Cargo.toml` | `use crate::`, `mod` |
| Java / Kotlin | `pom.xml`, `build.gradle(.kts)` | `import` |
| C# | `*.csproj`, `*.sln` | `using` |
| PHP | `composer.json` | `use` (PSR-4), `require` |
| Ruby | `Gemfile` | `require`, `require_relative` |
| Swift | `Package.swift` | `import` (Package targets) |
| C / C++ | `CMakeLists.txt`, `meson.build` | `#include "…"` |
| anything else | — | directory tree (dashed edges) |

## Usage

**1.** Put markers in your `README.md` (or skip — the block is auto-appended at EOF):

```markdown

<!-- ARCH_DIAGRAM_END -->
```

**2.** Add `.github/workflows/arch-diagram.yml` to your repo:

```yaml
name: architecture-diagram
on:
  workflow_dispatch:
  push:
    branches: [main, master]    # your default branch
    paths: ["src/**", "**.py", "**.js", "**.ts", "**.go"]  # your sources

permissions:
  contents: write

concurrency:
  group: repo2draw
  cancel-in-progress: true

jobs:
  sync:
    runs-on: ubuntu-latest
    if: ${{ !contains(github.event.head_commit.message, '[skip ci]') }}
    steps:
      - uses: actions/checkout@v5
      - uses: qiakai/repo2draw@main
      - name: Commit and push
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          if git diff --quiet -- README.md README.zh.md 2>/dev/null; then
            echo "README unchanged"; exit 0
          fi
          git add README.md README.zh.md 2>/dev/null || git add README.md
          git commit -m "docs: sync architecture diagram [skip ci]"
          git push
```

**3.** Push. The diagram appears between the markers on the first run and
stays current afterwards. (Live example: a workflow run analyzed
[qiakai/repo2draw-demo](https://github.com/qiakai/repo2draw-demo) and
committed the diagram itself.)

## Declare your own architecture (optional)

Auto-detection covers code, but not intent. Drop a `repo2draw.json` in the
repo root and repo2draw will draw exactly what you declare — this repo does
that for its own diagram (see [repo2draw.json](repo2draw.json)):

```json
{
  "title": "my system",
  "nodes": [
    {"id": "api", "type": "be", "label": "API Gateway"},
    {"id": "core", "type": "svc", "label": "core", "sub": "业务逻辑"},
    {"id": "db", "type": "db", "label": "PostgreSQL"}
  ],
  "edges": [
    {"from": "api", "to": "core"},
    {"from": "core", "to": "db", "variant": "main"}
  ]
}
```

Node types: `fe` `be` `db` `cloud` `sec` `bus` `svc` `ext`; edge variant:
`main` (emphasized) or `dash`. Grid auto-layout applies unless you pass
`"grid": {"row": 0, "col": 1}` per node.

## Configuration

All in the marked config block of `scripts/build_diagram.py`
(theme `shadcn` × 21 themes, `SCHEME`, `BOUNDARIES`, URL length limits)
and `scripts/update_readme.py` (`MARK_START`/`MARK_END`, `IMG_ALT`).

## How it works (skippable)

Three single-responsibility steps: `scripts/analyze_arch.py` (static
analysis → `arch.json`), `scripts/build_diagram.py` (`arch.json` → bare
x-cmd draw URL), `scripts/update_readme.py` (records the URL between the
markers, CRLF-safe, atomic). Cycle-safe SCC layering, keyword-based node
typing, top-level group boundaries. Diagram of this repository:
