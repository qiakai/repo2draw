# repo2draw

[English](README.md) | 中文

**零 AI 依赖的 README 架构图自动同步工具。**
静态分析你的仓库，把模块依赖渲染成 `x-cmd draw` 图表 URL，并自动保持
在 `README.md` 占位符之间持续更新——不调用任何大模型，不在仓库里提交
PNG/SVG，图就是一段 URL。

## 它能干什么

- **盯住你的仓库，自动刷新 README 架构图** —— push 到默认分支（仅源码路径）或手动触发，以 `github-actions[bot]` 身份回写提交。
- **认识 9 种项目语言**(Python、Node.js、Go、Rust、Java/Kotlin、C#、PHP、Ruby、Swift、C/C++)，不认识的仓库自动降级为目录树图——任何仓库都能出图。
- **零 AI、零依赖** —— 纯正则静态分析，只用 Python 3 标准库，一次运行约 10 秒；不需要任何 SDK 和 API key。
- **一行接入** —— workflow 里写 `- uses: qiakai/repo2draw@main` 即可，无需拷贝任何脚本。
- **图例诚实、清晰可读** —— 节点按模块名确定类型(Database / Frontend / Backend / Message bus…)，循环依赖安全分层，顶层目录自动分组，节点数封顶 15 个，绝不变成蜘蛛网。
- **仓库零图片文件** —— 图是 [x-cmd draw](https://x-cmd.com/draw) 按 URL 实时渲染的，git 历史里只有文本。

## 支持的项目语言

| 语言 | 检测特征 | 依赖提取来源 |
| --- | --- | --- |
| Python | `pyproject.toml` / `requirements.txt` / `setup.py` | `import`、`from X import Y`（含相对导入） |
| Node.js | `package.json` | `require`、`import … from`（含 `@/` 别名） |
| Go | `go.mod` | `import` 块 + module 路径 |
| Rust | `Cargo.toml` | `use crate::`、`mod` |
| Java / Kotlin | `pom.xml`、`build.gradle(.kts)` | `import` |
| C# | `*.csproj`、`*.sln` | `using` |
| PHP | `composer.json` | `use`（PSR-4）、`require` |
| Ruby | `Gemfile` | `require`、`require_relative` |
| Swift | `Package.swift` | `import`（Package Target） |
| C / C++ | `CMakeLists.txt`、`meson.build` | `#include "…"` |
| 其他 | — | 目录树结构（虚线边兜底） |

## 用法

**1.** 在你的 `README.md` 里加入占位符（跳过则自动追加到文末）:

```markdown

<!-- ARCH_DIAGRAM_END -->
```

**2.** 在你的仓库创建 `.github/workflows/arch-diagram.yml`:

```yaml
name: architecture-diagram
on:
  workflow_dispatch:
  push:
    branches: [main, master]    # 你的默认分支
    paths: ["src/**", "**.py", "**.js", "**.ts", "**.go"]  # 你的源码路径

permissions:
  contents: write

concurrency:
  group: repo2draw
  cancel-in-progress: true

jobs:
  sync:
    runs-on: ubuntu-latest
    if: ${{ !contains(github.event.head_commit.message, '[skip ci]') }}
    steps:
      - uses: actions/checkout@v5
      - uses: qiakai/repo2draw@main
      - name: Commit and push
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          if git diff --quiet -- README.md README.zh.md 2>/dev/null; then
            echo "README unchanged"; exit 0
          fi
          git add README.md README.zh.md 2>/dev/null || git add README.md
          git commit -m "docs: sync architecture diagram [skip ci]"
          git push
```

**3.** Push。首次运行就会生成架构图；之后每次源码变更自动刷新。
（真实案例：[qiakai/repo2draw-demo](https://github.com/qiakai/repo2draw-demo)
的 workflow 运行后自己提交了架构图。)

## 声明你自己的架构（可选）

自动分析覆盖代码，但覆盖不了意图。在仓库根目录放一个
`repo2draw.json`,repo2draw 就按你的声明画图——本仓库自己的架构图就是
这么来的（见 [repo2draw.json](repo2draw.json)):

```json
{
  "title": "my system",
  "nodes": [
    {"id": "api", "type": "be", "label": "API Gateway"},
    {"id": "core", "type": "svc", "label": "core", "sub": "业务逻辑"},
    {"id": "db", "type": "db", "label": "PostgreSQL"}
  ],
  "edges": [
    {"from": "api", "to": "core"},
    {"from": "core", "to": "db", "variant": "main"}
  ]
}
```

节点类型：`fe` `be` `db` `cloud` `sec` `bus` `svc` `ext`；连线 `variant`:
`main`（强调）或 `dash`（虚线）。默认自动分层布局，也可以在节点上加
`"grid": {"row": 0, "col": 1}` 手工指定。

## 配置

都在脚本的配置区里：`scripts/build_diagram.py`（主题 `shadcn` 共 21 种、
`SCHEME`、`BOUNDARIES`、URL 长度上限）和 `scripts/update_readme.py`
(`MARK_START`/`MARK_END` 占位符、`IMG_ALT`)。

## 实现细节（可跳过）

三个单一职责脚本串成流水线：`scripts/analyze_arch.py`（静态分析 →
`arch.json`)、`scripts/build_diagram.py`(`arch.json` → 裸 x-cmd draw URL)、
`scripts/update_readme.py`（把 URL 记录进占位符之间，CRLF 安全、原子写）。
循环依赖经 SCC 缩点分层，节点类型按模块名映射，顶层目录自动成组边界。

本地开发：`make arch`（三步）、`make verify`（校验全部内嵌 URL)、
`make clean`。不想用 `uses:` 引用？把三个脚本拷进你的仓库，再复制
`.github/workflows/sync-arch.yml` 即可自托管。
